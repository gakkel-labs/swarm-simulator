# Contributing

[Français](CONTRIBUTING.fr.md)

Solo project, written to stay readable and extensible.

## How to run locally

See [Try it in README.md](README.md#try-it): start the Java backend with Maven, open the Unity
viewer, hit Play. No database, no external services — only port `50051` must be free.

---

## Coding conventions

**Java (backend)**
- Java 21 — records, sealed classes, pattern matching are welcome.
- [Google Java Style Guide](https://google.github.io/styleguide/javaguide.html): 4-space indent, 100-column limit.
- No Spring Boot for now: `main()` + `ScheduledExecutorService` + `ServerBuilder` only
  ([ADR-0002](docs/adr/0002-no-spring-boot-for-mvp.md)). Spring Boot is planned for Step 4.
- Tests first (TDD): write a failing test, then the smallest code that makes it pass, then refactor.
- Tests: JUnit 5 + Mockito, AAA pattern, descriptive method names.
- Variable names must be explicit — no single-letter or abbreviated identifiers.
- New classes use the words of the [glossary](docs/produit/glossaire.md) (`Mission`, `Fleet`,
  `SearchArea`, `Contact`…).

**Protobuf** — definitions in `contracts/`, proto3, snake_case fields. Do not break the
`WorldState` streaming contract without bumping the package version. The C# code in
`unity-client/Assets/Scripts/Grpc/Generated/` is generated by `contracts/generate-csharp.ps1`:
do not edit it by hand.

**Docs** — every doc exists in English (`X.md`) and French (`X.fr.md`), with a link to the other
language at the top. An accepted ADR is not edited: write a new ADR instead
([template](docs/adr/TEMPLATE.md)).

**Commits** — [Conventional Commits](https://www.conventionalcommits.org/), imperative mood:
```
feat(boids): add lateral avoidance when obstacles are flanked
fix(grpc): close stream cleanly on server shutdown
docs(readme): add Unity setup screenshots
```
Valid scopes: `boids`, `domain`, `agent`, `server`, `grpc`, `proto`, `contracts`, `unity`, `ci`,
`docs`. For docs, the scope can name the part: `docs(readme)`, `docs(adr)`, `docs(produit)`.

## Pull request process

1. CI must be green (Maven build + JUnit tests) before merge.
2. Prefer small, focused PRs — one concern per PR.
3. Reference the issue in the description (`Closes #N`).
4. No WIP merges — draft PRs are fine to share early, merge only when ready.

---

## Reporting issues

Issues are written in simple English. Include: what you expected, what happened (stack trace /
log / Unity console error), reproduction steps (JDK version, Unity version, OS), and a label
(`bug`, `enhancement`, or `question`).

For design or architecture questions, open a Discussion instead.
