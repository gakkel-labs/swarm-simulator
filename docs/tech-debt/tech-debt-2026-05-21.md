## 🔴 Important debt (to handle before v0.2)

### 1. Empty `tests/` module
`tests/pom.xml` exists but there is no `.java`. No end-to-end integration test (gRPC client →
server → WorldState). All tests are unit tests. The coordinate conversion NED↔server↔Unity
(3 different transformations) is not checked end to end anywhere.

### 2. Coordinate conversion duplicated and fragile
- `SwarmObserverImpl.toVec3` (`SwarmObserverImpl.java:154-163`): server→NED
- `SimulationControlImpl.placeTarget` (`SimulationControlImpl.java:38`): NED→server
- `SwarmVisualizer.NedToUnity` (`SwarmVisualizer.java:254`)
- `TargetRenderer.NedToUnity` (`TargetRenderer.java:70`)
- `TargetPlacer` (`TargetPlacer.java:42-47`): Unity→NED inverse

5 independent implementations of the same mapping. One mistake on an axis = a positioning bug
that is hard to isolate. To centralise: one server utility + one Unity utility, tested.

### 3. Duplicated `SimulationLoop.main()`
`SimulationLoop.java:353-372`: a `main()` that starts the loop without the gRPC server. Probably
left from exploration. Source of confusion — a developer could run it thinking they run the real
simulation. To remove (the real entry point is `SwarmServer.main`).

### 4. `Predator`: non-atomic volatiles
`Predator.java:11-12` — `position` and `velocity` are `volatile` but updated separately in
`update()`. A future observer (another thread) can read a pair (position t+1, velocity t). It is
latent: today only the sim thread reads them, but `Agent` was already refactored for the same
problem and `Target` uses `AtomicReference`. Consistency to restore before exposing a parallel
read channel.

## 🟡 Moderate debt

### 5. Magic numbers hard-coded in several places
- ~~`SimulationLoop.SENSOR_RADIUS = 20.0`~~ → moved to `SimulationConstants.SENSOR_RADIUS_M` (2026-05-21)
- `Predator.SPEED = 3.0` / `EAT_RADIUS = 1.5` (`Predator.java:8-9`) — not configurable, not
  testable with other values
- `SwarmVisualizer.SpawnFloor` (`SwarmVisualizer.java:354-365`): floor position hard-coded
  (`Y=-100`, scale 10×5) with a comment saying it matches the server sizes. If
  `DEFAULT_WORLD_*` changes on the Java side, the floor is silently misaligned. The `WorldState`
  proto could carry the sizes.

### 6. Non-deterministic `Random` in `BoidsRules`
`BoidsRules.java:16`: `new Random()` with no seed. `wander()` is not repeatable between runs →
fragile simulation tests, replay impossible. A seed (env var or flag) would solve it.

### 7. No external configuration
Port 50051, agentCount=20, Boids configs, world sizes — all hard-coded. For v0.2 (Docker) it
will have to be configurable anyway. A minimal `application.properties` or env vars would be
enough, no need for Spring.

### 8. `World.neighbors()` in O(n²)
`World.java:67-74` — fine at 20 agents (400 ops × 30 Hz). At 100 agents (10k ops/tick) it is
still fine but starts to cost. If the v0.4 roadmap aims at bigger swarms, a uniform spatial grid
is needed.

### 9. Missing ADRs
`docs/adr/` only contains `0004` (and the TEMPLATE). The structuring decisions (no Spring, gRPC
streaming, NED, immutability strategy) are not recorded as ADRs, although CLAUDE.md refers to them.

### 10. Unchecked cast in `SwarmObserverImpl`
`SwarmObserverImpl.java:60` — `(ServerCallStreamObserver<WorldState>) responseObserver` with no
type check. gRPC guarantees it in practice, but a comment or an `instanceof` would make the
invariant explicit.

## 🟢 Minor details

### 11. `SwarmObserverImpl`: side effect in the constructor
`SwarmObserverImpl.java:52` starts `scheduleAtFixedRate` in the constructor. It makes tests
harder (already worked around with a package-private constructor + mocked executor). A separate
`start()` method would be cleaner.

### 12. Hard-coded `predator-0`
`SwarmObserverImpl.java:131`: fixed predator ID. If v0.x adds several predators, to refactor.

### 13. `Vector3D.distanceTo` allocates a temporary object
`Vector3D.java:32`: `subtract(other).magnitude()` creates an object. On the 30 Hz hot path it is
negligible today, but `World.neighbors` already has its own private `squaredDistance` — a public
`distanceSquaredTo` avoids the duplication and the allocation.

### 14. `World.addAgent.contains()` in O(n)
`World.java:35` — fine at 20 agents. A duplicate `Set<UUID>` would be cleaner if we scale.
